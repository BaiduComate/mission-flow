# AGENTS 生成指导

AGENTS 是项目知识的导航入口，每次会话都会被读入。指令数量和长度直接影响 agent 的遵循度：内容越多、越不通用，agent 越容易整体忽略。保持紧凑，控制在 100 行以内；详细架构、流程和平台约定放在对应文档，AGENTS 只给指引不复制内容。

## 调研重点

- 从 README、manifest 和入口文件确认项目用途，只写一句话。
- 从 package scripts、任务运行器和 CI 配置确认最常用且可执行的命令。
- 从已有指令文件、工具配置和实际代码提取 agent 容易遗漏的项目约束。
- 从 formatter、linter 和代表性源码确认与语言或框架默认不同、且工具管不到的编码风格：命名规范、import 风格、目录归属等语义约定；缩进、引号等能被 formatter 强制的规则不算。
- 从分支、提交历史、贡献指南和 CI 确认简短的研发流程。
- 收集项目已有的高价值文档，只索引真实存在且后续工作需要读取的文件。
- 涉及大量历史或多个配置文件时派子代理调研，只采用验证过的结论，不采用差异或错误分析。
- 每条候选内容用一个问题筛选：删掉这条，agent 会不会因此做错事。答不上来就不写。

## 生成要求

使用 `templates/agents.md` 作为结构起点，并按实际情况增删章节。

- 文档索引只指向实际生成或已经存在的文件，使用正确的相对路径和大小写；只给去哪找的指引，不复制目标文档的内容。
- 常用命令只放最需要的精确调用，包含容易猜错的 flag、目录或执行顺序。
- 核心约束保留 5 到 10 条高信号规则，平铺成 bullets；每条自测“删掉这条，agent 会不会因此做错事”，答不上来就删。
- 编码风格是可选的章节，只写语言或框架默认不同、且无法被 formatter/linter/typecheck 强制执行的约定；能被工具自动检查或修复的规则不写在这里，应配置对应工具。
- 研发流程控制在 3 到 5 行，说明分支模型、评审方式和提交前验证要求。
- 未生成的可选文档不要出现在索引中。
- 正文控制在 100 行以内。内容变多不是加长的理由，超出时先精简或删除不再高频触发的条目，仍不够再考虑拆到 `docs/` 下的独立文件并在文档索引中链接。

## 避免

- 不复制 ARCHITECTURE、WORKFLOW 或 ICAFE 的详细内容。
- 不写通用软件工程建议、完整脚本清单或穷尽式目录树。
- 不根据平台相似性猜测评审、项目管理或 CI 工具名称。
- 不写 agent 靠读代码、跑一次 lint 或查一次文档就能自己获得的信息。
- 不写会被 formatter、linter 或 typecheck 强制执行的风格规则，交给工具配置而不是文字描述。
- 不写容易过时的具体事实（版本号、临时状态、进行中的迁移），除非同时标注时间点或来源。
- 不整段复制 API 文档或配置项清单，改成指向权威来源的链接。
