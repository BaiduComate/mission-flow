# ARCHITECTURE 生成指导

ARCHITECTURE 用于快速定位系统，不用于穷尽实现细节。描述高层结构、模块或包边界、依赖方向。

## 调研重点

- 从 workspace 配置、manifest 和目录结构确认应用、库、服务及其边界。
- 读取少量装配入口、路由入口、服务启动文件或依赖注入配置，确认真实执行流。
- 从 import、构建配置和包声明确认依赖方向，不只依据目录名推断。
- 识别改变开发方式的外部系统，例如数据库、消息系统、对象存储或第三方服务。
- monorepo 需要确认各包职责以及构建或依赖顺序。

## 生成要求

使用 `templates/architecture.md` 作为结构起点，并按系统实际结构调整图和章节。

- Mermaid 图选择通信流、数据流或依赖图中最能解释系统的一种，不必把所有文件和服务都画进去。
- Mermaid 节点 ID 使用稳定的 ASCII 标识；项目名、包名和说明放在带引号的节点文本中，不把占位符或路径直接用作节点 ID。
- 图后必须有图例，每行说明一个主要组件是什么、位于哪里。
- 模块边界说明职责和所有权，依赖方向说明允许和禁止的方向。
- 生成后实际解析 Mermaid，确认括号、边和节点引用有效。

## 避免

- 不写详细 API 清单、配置项大全或逐文件说明。
- 不把名称相近的目录自动视为相互依赖。
- 不为填满模板而虚构数据库、缓存、前后端或外部服务。
