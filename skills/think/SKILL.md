对开发者进行进行周详的提问，直至双方对需求达成一致的理解。提问可以是很多轮，`前一轮提问的结果` + `调研后获取的信息`共同决定下一轮的提问方向和内容，如此一轮轮进行提问，直到需求理解完善结束本流程

提问时使用 question 工具，为每轮提问进行编号，并提供推荐答案，格式如下：

```
**Q1** - **<question title>**: <question body, might be multiple paragraphs, including multiple choices>
```

## 提问准则

1. 积极获取环境中已有信息：当问题需要从环境中（代码库、网络等）获取事实时，请派遣子代理去查找，不要向使用者询问任何你可以自行查找的信息。同时不要因调研让流程受阻，可以立刻提出当轮其他不被调研所阻止的问题，当所有完成后准备下一轮提问。
2. 提问的决策树是动态可重塑的：一轮提问的结果配合上环境中已有的知识，有可能解锁依赖于这些决策的问题，这时候需要重新思考并提出下一轮问题。如果某个问题的答案依赖于本轮中尚未解决的另一个问题，则该问题属于**后续**轮次，而非当前轮次
3. 注重提问的艺术：语言要**精炼平实**

## 推进范围

需求理解对齐后，用 question 确认本次推进到哪一步。选项由项目 workflow.md 定义，workflow.md 没有声明时用默认两项：

- 端到端：实现、验证，直到可提交
- 只实现：写完并验证，不提交

用户在需求里已经说清推进范围时跳过这次询问
